# URL Shortener

HTTP-сервис на Go для создания коротких ссылок и получения исходного URL по коду. Поддерживает два взаимозаменяемых хранилища: PostgreSQL и память процесса.

Основной инвариант: **каждому сохранённому URL соответствует один код, каждому коду — один URL**. Он сохраняется при повторных и конкурентных запросах.

## Ключевые решения

### Генерация и уникальность

Код состоит из 10 символов алфавита `a–z`, `A–Z`, `0–9`, `_`. Источник случайности — `crypto/rand`. При преобразовании байтов в символы используется rejection sampling: значения 252–255 отбрасываются, чтобы все 63 символа имели одинаковую вероятность.

Генератор предлагает кандидата; уникальность обеспечивает хранилище. Если URL уже существует, сервис возвращает сохранённую пару. Если код занят другим URL, генерация повторяется. Число попыток ограничено восемью: при исчерпании сервис возвращает `503`, сохраняя существующие записи.

Пространство кодов содержит `63^10 ≈ 9,85 × 10^17` комбинаций. Большой размер снижает частоту коллизий; корректность решения обеспечивается атомарной записью и обработкой конфликтов.

### Хранение и конкурентный доступ

**Memory.** Две map обеспечивают поиск по коду и исходному URL. Проверка ограничений и обновление обоих индексов выполняются под одной блокировкой `sync.RWMutex`. Чтения используют разделяемую блокировку. Лимит записей ограничивает рост хранилища: после его достижения новые URL отклоняются, существующие остаются доступны.

**PostgreSQL.** `PRIMARY KEY(code)` и `UNIQUE(original_url)` обеспечивают уникальность независимо от количества экземпляров приложения. Запись выполняется через `INSERT … ON CONFLICT DO NOTHING`; при конфликте отдельный запрос по URL возвращает запись конкурента либо сообщает о занятом коде. Отдельное чтение получает новый снимок данных. Повторный запрос не вызывает фиктивного `UPDATE` существующей строки.

Предварительный поиск по URL сокращает работу при повторах; окончательная проверка остаётся внутри операции сохранения. SQL-запросы параметризованы, пул ограничен десятью соединениями на экземпляр.

### Границы ответственности

HTTP-слой отвечает за протокол, сервис — за правила создания ссылок, реализации хранилища — за атомарность и доступ к данным. Контракт `Store` позволяет менять способ хранения без изменения сервисной логики.

| Пакет | Ответственность |
|---|---|
| `cmd/shortener` | Сборка зависимостей и жизненный цикл приложения |
| `internal/config` | Параметры запуска и их проверка |
| `internal/shortener` | Модель, валидация, генерация, обработка коллизий |
| `internal/httpapi` | Маршруты, JSON, HTTP-статусы |
| `internal/storage/memory` | Хранение в памяти с синхронизацией |
| `internal/storage/postgres` | PostgreSQL, схема и SQL-запросы |

Используются стандартный `net/http` и драйвер `pgx/v5`; HTTP-фреймворк и ORM не требуются.

## HTTP API

| Метод и маршрут | Результат |
|---|---|
| `POST /api/links` | Создание ссылки: `201 Created`; существующий URL: `200 OK` |
| `GET /{code}` | Исходный URL: `200 OK`; отсутствующий код: `404 Not Found` |
| `GET /healthz` | Проверка работы HTTP-сервера |
| `GET /readyz` | Проверка доступности хранилища |

Создание ссылки:

```http
POST /api/links
Content-Type: application/json

{"url":"https://example.com/catalog?item=42"}
```

Пример ответа:

```json
{
  "code": "aB3_dE5fG7",
  "short_url": "http://localhost:8080/aB3_dE5fG7",
  "original_url": "https://example.com/catalog?item=42"
}
```

`GET` по возвращённому `short_url` выдаёт:

```json
{"original_url":"https://example.com/catalog?item=42"}
```

Длина 10 символов относится к **коду**. GET возвращает JSON без перенаправления браузера. Главная веб-страница не предусмотрена: для проверки доступности используется `/healthz`, корневой маршрут `/` возвращает `404`.

Ошибки имеют единый формат:

```json
{"error":{"code":"not_found","message":"Link not found"}}
```

Некорректный ввод возвращает `400`, неподдерживаемый метод — `405`, превышение размера тела — `413`, неверный Content-Type — `415`. Неожиданные внутренние ошибки дают `500`; таймаут, заполнение memory-хранилища и исчерпание попыток генерации — `503`. Внутренние ошибки и параметры подключения не раскрываются клиенту.

## Надёжность и ограничения

- Принимаются абсолютные HTTP/HTTPS URL длиной до 2048 байт UTF-8, без userinfo, пробельных и управляющих символов. Ограничение длины позволяет индексировать исходную строку целиком в стандартной конфигурации PostgreSQL.
- URL сравниваются точно, без нормализации: порядок параметров и регистр пути могут влиять на смысл адреса. Сервис не обращается к целевому сайту.
- Размер тела запроса ограничен 16 KiB. Заданы HTTP-таймауты и трёхсекундный таймаут операции хранилища. При завершении процесса текущим запросам предоставляется до десяти секунд.
- Memory рассчитан на один процесс и теряет данные при перезапуске. PostgreSQL сохраняет данные и поддерживает несколько экземпляров приложения с общей БД. Автоматическое удаление и изменение ссылок не предусмотрены.
- Для длительной эксплуатации PostgreSQL нужны контроль диска, обслуживание и резервное копирование. Для публичного доступа — TLS и ограничение нагрузки. Авторизация, TTL и аналитика переходов находятся вне объёма реализации.

## Запуск

**Локально, Go 1.26.1+:** из каталога с `go.mod` выполните команды по очереди:

```sh
go mod download
go run ./cmd/shortener -storage=memory
```

Проверка: `http://localhost:8080/healthz`. Остановка — `Ctrl+C`.

**PostgreSQL и приложение в Docker Compose:** создайте `.env` из `.env.example`, задайте `POSTGRES_PASSWORD` и выполните:

```sh
docker compose up --build -d
```

Compose последовательно запускает БД, инициализацию схемы и приложение. HTTP доступен на `localhost:8080`; данные PostgreSQL сохраняются в именованном томе. Остановка: `docker compose down`.

**Docker-образ с memory-хранилищем:**

```sh
docker build -t url-shortener:local .
docker run --rm -p 127.0.0.1:8080:8080 url-shortener:local -storage=memory
```

Финальный образ содержит статический бинарник и CA-сертификаты и запускается от непривилегированного пользователя.

Основные параметры: `-storage=memory|postgres`, `-addr=:8080`, `-base-url=http://localhost:8080`, `-memory-limit=100000`. Для PostgreSQL вне Compose необходима переменная `DATABASE_URL` и предварительный запуск с `-storage=postgres -migrate`. Полный список: `go run ./cmd/shortener -h`.

## Проверка

Unit-тесты не требуют внешних сервисов:

```sh
go test ./...
go vet ./...
```

Unit- и интеграционные тесты PostgreSQL с race detector:

```sh
docker compose -p shortener-tests -f compose.test.yaml up --abort-on-container-exit --exit-code-from tests
docker compose -p shortener-tests -f compose.test.yaml down
```

Проверяются HTTP-контракт, валидация, повторное создание, коллизии, ошибки зависимостей, лимиты и конкурентный доступ. Интеграционные тесты включают 300 запросов к одному URL через два независимых пула. CI также предусматривает сборку и проверку запуска Docker-образа.
